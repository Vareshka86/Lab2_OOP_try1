# Часть 2. Изменение состояния, деструктор и счётчик объектов {#state}

[TOC]

Версия v0.2. Класс Book получил методы изменения состояния, явный деструктор и статический
счётчик существующих объектов — элементы, которые спроектированы на странице @ref design.

## Что требуется

Из обязательных требований лабораторной работы:

- класс должен иметь минимум три метода, изменяющих состояние объекта; бессмысленных
  setter-методов быть не должно;
- класс должен обеспечивать корректность собственного состояния;
- деструктор определяется явно и показывает момент завершения времени жизни объекта;
- в класс добавляется статический счётчик количества существующих объектов.

## Как решено

| Метод | Что делает | Когда отказывает | Инварианты |
|-------|------------|------------------|------------|
| `issueTo(reader)` | выдаёт книгу: записывает читателя, увеличивает число выдач | книга списана; уже выдана; имя читателя пустое | 3, 4, 5 |
| `returnBook()` | возвращает книгу на полку, стирает имя читателя | книга не выдана | 3 |
| `writeOff()` | списывает книгу | книга уже списана; книга у читателя | 4 |
| `~Book()` | уменьшает счётчик и сообщает об уничтожении | — | — |
| `getCount()` | возвращает число существующих книг (статический метод) | — | — |

Это действия библиотеки, а не сеттеры: нет `setIssued(true)` или `setReaderName(...)`, через
которые можно было бы записать в книгу противоречивое состояние.

## Отказ без изменений

Каждый метод изменения сначала выполняет **все** проверки и только потом меняет поля:

```cpp
bool Book::issueTo(const std::string& reader)
{
    if (isWrittenOff_) { std::cout << "  Отказ: ... списана ...\n"; return false; }
    if (isIssued_)     { std::cout << "  Отказ: ... уже у читателя ...\n"; return false; }
    if (reader.empty()) { std::cout << "  Отказ: не указано имя читателя.\n"; return false; }

    isIssued_ = true;      // изменения - только когда все проверки пройдены
    readerName_ = reader;
    ++issueCount_;
    return true;
}
```

Если операция недопустима, метод возвращает `false`, сообщает причину и не трогает ни одно поле,
поэтому книга остаётся в прежнем корректном состоянии. Конструктор так поступить не может — он
ничего не возвращает — и при неверных данных бросает исключение (см. @ref design).

## Статический счётчик

```cpp
// Book.h
static int count_;          // объявление: одно поле на весь класс
static int getCount();

// Book.cpp
int Book::count_ = 0;       // определение - в C++14 обязательно в .cpp
```

Обычное поле есть у каждого объекта своё, а статическое — одно на весь класс. Счётчик
увеличивают **все три конструктора**, включая конструктор копирования, и уменьшает деструктор.
Если бы конструктор копирования не увеличивал счётчик, после уничтожения копий счётчик стал бы
отрицательным.

В параметризованном конструкторе `++count_` стоит после всех проверок: если конструктор бросил
исключение, объект не создан, деструктор для него не вызывается — и считать его нельзя.

Присваивание `a = b` новой книги не создаёт, поэтому оператор присваивания счётчик не трогает:
он объявлен как `Book& operator=(const Book& other) = default;` — стандартное копирование полей.
Явное объявление показывает, что присваивание продумано: у класса есть свои конструктор
копирования и деструктор (правило трёх).

## Деструктор и время жизни

Деструктор `~Book()` вызывается автоматически, когда время жизни объекта заканчивается:

- локальный объект — при выходе из блока `{ }`, в котором он объявлен;
- объекты одного блока уничтожаются в порядке, **обратном** созданию;
- объект, созданный через `new`, — при `delete`.

Класс не выделяет динамической памяти, поэтому деструктору освобождать нечего; он уменьшает
счётчик и выводит сообщение, по которому видно, когда объект перестал существовать. Чтобы эти
сообщения появились до паузы в конце программы, демонстрация вынесена в функцию `runDemo()`:
все книги — её локальные объекты и уничтожаются при выходе из неё.

## Пример работы программы (v0.2)

```
=== Методы изменения состояния ===
war.issueTo("Иванов И. И.")
  -> выполнено
Книга «Война и мир»
  Автор:        Лев Толстой (род. 1828)
  Год издания:  1869
  Положение:    выдана читателю: Иванов И. И.
  Число выдач:  1
war.issueTo("Петров П. П.")   // книга уже выдана
  Отказ: книга «Война и мир» уже у читателя (Иванов И. И.).
  -> отклонено
war.writeOff()   // книга у читателя
  Отказ: книга «Война и мир» у читателя (Иванов И. И.), сначала её нужно вернуть.
  -> отклонено
war.returnBook()
  -> выполнено
war.writeOff()
  -> выполнено
...
=== Время жизни объектов и счётчик ===
Book::getCount() = 2
{   // начало блока
  [+] Создана книга «Мастер и Маргарита» (конструктор копирования). Книг сейчас: 3
  [+] Создана книга «Без названия» (конструктор по умолчанию). Книг сейчас: 4
    Внутри блока Book::getCount() = 4
}   // конец блока: объекты copy и empty уничтожаются
  [-] Уничтожена книга «Без названия» (деструктор). Книг сейчас: 3
  [-] Уничтожена книга «Мастер и Маргарита» (деструктор). Книг сейчас: 2
После блока Book::getCount() = 2

Конец функции runDemo(): уничтожаются war и master (в обратном порядке создания)
  [-] Уничтожена книга «Мастер и Маргарита» (деструктор). Книг сейчас: 1
  [-] Уничтожена книга «Война и мир» (деструктор). Книг сейчас: 0

После runDemo() Book::getCount() = 0
```

**Проверка.** Отдельная тестовая программа — 35 проверок из 35: счётчик при каждом из трёх
конструкторов, при исключении в конструкторе (не меняется), при присваивании (не меняется), при
выходе из блока, при `new` и `delete`; успешные операции; каждый отказ оставляет книгу без
изменений; копия книги независима от оригинала. Проверки части 1 (23 из 23) проходят по-прежнему.
